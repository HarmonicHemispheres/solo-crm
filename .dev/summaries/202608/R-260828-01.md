## What changed

The project went from a task plan and a mockup to a running, sealed, tested
Electron skeleton: a renderer that boots into the real app shell over design
tokens lifted verbatim from the mockup, a main process that owns an
18-table SQLite database behind WAL, migrations and a sync-folder guard, and
a typed, zod-validated IPC bridge with TanStack Query as the renderer's only
data layer. Every architectural decision the plan left open (G1–G8, the
Pipeline view) is now an ADR, and a seed fixture makes the dev loop real.
All 13 tasks merged; 351 tests and four verify gates are green on `main`.

## Decisions

Structural ones, each an ADR:

- [ADR-001](../../decisions/ADR-001-touch-timestamps.md) — touch/staleness
  timestamps (NaN staleness renders maximally stale, never fresh)
- [ADR-002](../../decisions/ADR-002-settings-key-value-table.md) — `settings`
  and `favicons` keyed by natural identity, exempt from the UUID rule
- [ADR-003](../../decisions/ADR-003-materialised-revenue.md) — revenue
  materialised into `revenue_lines`; generator owns estimate supersession
- [ADR-004](../../decisions/ADR-004-credential-storage.md) — safeStorage
  with a `basic_text` backend guard, never plaintext fallback
- [ADR-005](../../decisions/ADR-005-pipeline-view.md) — the Pipeline view
  does not ship; its absence is asserted by tests

Mid-run orchestrator calls that outlive the run, recorded in the task
outcomes rather than ADRs: activity back-link FKs stay RESTRICT (history
blocks deletion, with a message saying why — reversible if it grates in
use); `staleTime: Infinity` with correctness from explicit per-entity
invalidation (CONVENTIONS.md "Query cache" argues it in full);
`optimisticUpdate` requires its `reconcile` helper by signature; the preload
is CJS with bundled deps because sandboxed renderers reject ESM preloads;
the shell's Esc dismissal is owned solely by LayerManager — `Sheet`'s own
listener is an opt-out the manager exercises.

## What went wrong

Honest list, because the next run should be faster and cleaner:

- **The first process loop was too heavy, and it was the orchestration, not
  the skills.** Two reviewers per task plus fix-everything-then-re-review
  rounds had the run stuck on the first two tasks long enough for Robby to
  flag it. Switched mid-run to one combined review per task, merge unless
  blocking, orchestrator applies precise fixes at merge, follow-ups over
  fix rounds. Every task after the switch closed in one review cycle.
- **The run took all night (~8h) for 13 tasks, and concurrency was never the
  limit.** The 8-deep dependency spine at 45–70 min per link was: build +
  review + merge is serial per link, worktrees paid cold `npm install`
  (Electron download included) every time, and five fix rounds landed on
  spine tasks. Levers for next run, ranked: scope tasks so shared files are
  the serialization unit; speculative pipelining (dispatch the next spine
  builder from the unreviewed branch, discard on a blocking verdict —
  ~40% block rate this run still nets positive); shared node_modules +
  `ELECTRON_CACHE`; opus/xhigh reviews only where a missed defect is
  expensive (data/ipc); a builder watchdog at 2× median build time —
  T-260828-12 built for 2h22m before anyone looked.
- **Every agent worktree spawned at a stale HEAD** (`989c054`) rather than
  main's tip, so every prompt needed a base-check-and-rebranch preamble.
  Worth fixing in the spawn path, not the prompt.
- **Reviews earned their cost — green tests certified broken code five
  times.** An ESM preload that never loaded, a design system never imported
  at runtime, optimistic rollback as a silent no-op behind two vacuous
  tests, seed data written to the wrong userData directory, and T-12's Esc
  handler closing two layers — each found by review, each behind passing
  tests. The pattern both times tests lied: the test exercised the
  mechanism, never the integration (imported at runtime? fired in the
  reverse order?).
- **Real-window Electron boot tests flaked under parallel load** (the
  kill-mid-transaction test twice); fixed with a readiness handshake
  instead of sleeps, but the lesson is to run boot-real tests serially.
- **Index discipline slipped twice** — frontmatter updated without the
  index (T-08) and duplicate rows left behind (T-05/06, caught by Robby
  after the run). The dashboard is only worth keeping if every transition
  touches file + index together, in the same commit.
- One `git add -A` staged a user file that was never the run's to touch
  (caught, amended); explicit paths only thereafter. A PowerShell 5.1
  `-replace` re-encoding corrupted a UTF-8 source file during T-12's
  mutation check (caught by the test run, restored) — on Windows, file
  surgery belongs to the file tools, not the shell.
