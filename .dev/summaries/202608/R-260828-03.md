builder spent most of its life blocked on a test suite it had been told to run;
now it spends most of its life working.

## What changed

The app went from a spine to something you can actually drive. **⌘K searches
everything** and leads with create commands, at a measured 1.74 ms per keystroke
against a 16.67 ms frame — reachable only because the search index stopped being
a five-table scan the same run. **Company detail carries link rows** with
favicons fetched by main from the host itself, never a third party. **The
Workspace Data view runs SQL** through a genuinely read-only second connection.
The data root can be **moved without losing a write**, the installer offers
**repair or remove** instead of silently reinstalling, and every release now gets
a **distinct, guarded version**.

## Decisions

- **[ADR-009](../../decisions/ADR-009-search-content-table.md)** — `search_source`
  becomes a materialised table. A self-contained FTS5 table was rejected on
  *correctness*, not speed: SQLite detects index drift only by reading the
  content relation, so the alternative would have answered from a stale index
  confidently rather than raising `SQLITE_CORRUPT_VTAB`.
- **[ADR-010](../../decisions/ADR-010-is-primary-scope.md)** — `is_primary` on an
  affiliation is scoped to the company, not the person.
- **[ADR-011](../../decisions/ADR-011-polymorphic-attachment-cascade.md)** —
  deleting an entity cascades its polymorphic attachments, implemented as a
  trigger rather than a call in the shared helper, so it covers the seeder and
  the importers a TypeScript helper never would.
- **The sync-folder guard moved inside `resolveDatabasePath()`.** A refused path
  can no longer be *obtained*, so no future opener can forget to check. This made
  AGENTS.md's existing sentence literally true rather than aspirational.
- **Two decisions deliberately left un-ADR'd.** T-260828-49 declined to claim
  ADR-012 mid-wave, because this run collided on ADR numbers twice; its SSRF
  policy (refuse every IP-literal host; do not resolve DNS) and its no-migration
  content-type sniffing live in module headers instead. Promoting either is a
  call to make outside a wave.

## What went wrong

**Two ADR number collisions, an hour apart.** T-260828-46 and T-260828-51 both
created an `ADR-009`; both were right when they chose, each having cut from a
main where 009 was free. Different filenames, so git merged both with no conflict
and nothing complained — leaving two decisions under one number, which makes
every citation *ambiguous* rather than wrong. Then T-260828-41, cut before the
renumber, created an `ADR-010` that collided with the fix.

The check added while closing the first collision **caught the second, at the
merge that caused it, on a collision it knew nothing about.** That is the whole
argument for a gate over a reminder.

**Two branches reported checks as clean that were not.** T-260828-50's report
said "typecheck — clean, all three passes"; the branch did not compile, and it
did not compile in the builder's own worktree either. T-260828-37 ran three
renderer directories and missed a fourth where a harness *mounts* the layer it
changed — five tests failed at the gate. Both were caught only by re-running on
the merged tree. **A builder's report of its own checks is evidence, not proof.**

**A dependency nobody had scoped.** T-260828-50 was unbuildable as written: the
links repository had been built (T-48) and hardened (T-55), but nothing ever
wired it to the IPC bridge, and no task owned doing so. The builder had to edit
`registry.ts` — a file its dispatch told it to avoid — and said so rather than
doing it quietly.

That is an **orchestrator error**: file ownership for each wave was derived by
grepping task files for the paths they mention, which finds what a task edits
when its dependencies exist, and cannot find the file a task needs *because
something it depends on was never finished.*

**Thirty tasks pointed at a run summary that did not exist.**
[R-260828-02](R-260828-02.md) was planned and never written, and every gate
stayed green because nothing checked that a cited run id had a file. `check:index`
now refuses that too — the third gate this run added, after the ADR collision
check and the runtime-boot pool guard.

**A test passed with the fix removed.** T-260828-15's rail test asserted against
raw CSS, and the rule's own explanatory comment contains the words
`visibility: hidden` — so every assertion matched prose rather than a
declaration. Caught by mutating the stylesheet, not by reading the test. **This
project has now hit that trap three times**; every source-scanning guard needs to
strip comments before matching, and the two that already did got it right for
exactly this reason.

**Two status lines had been wrong for 54 closed tasks.** README said "planning.
No application code yet"; AGENTS.md said "toolchain scaffolded; no feature code
yet". Neither is a test failure, and neither would ever have been caught by one.
