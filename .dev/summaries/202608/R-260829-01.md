## Decisions

- **Migration numbers were assigned before dispatch, not at merge.** 04 and 10
  both scoped themselves as `0005`. Two files claiming one number do not conflict
  textually in git — the filenames differ — so it would have surfaced as a
  runtime ordering surprise rather than a merge conflict. 04 took `0005`, 10 took
  `0006`, stated in both dispatch prompts. Nothing had to be renumbered.
- **[ADR-012](../../decisions/ADR-012-operator-branding-storage.md)** — branding
  bytes live in the database, not as files in the data root, and not as a
  `settings` key. Keyed by `slot` under ADR-002's natural-identity exemption.
- **0006 is a plain `ALTER TABLE … RENAME`, not a table rebuild.** SQLite's docs
  read as though `REFERENCES` rewriting depends on `PRAGMA foreign_keys`, and
  `migrate.ts` runs migrations with foreign keys **off**. Probed directly before
  the migration was written: the rewrite is governed by `legacy_alter_table` and
  happens in both states. A rebuild would have dropped `engagements`' search
  triggers and 0004's indexes with it.
- **The mockup's brand block is now a documented divergence**, annotated in the
  mockup itself and in AGENTS.md's References section beside the Pipeline/ADR-005
  exception — because AGENTS.md calls the mockup authoritative, and an
  undocumented departure reads as a defect to fix back.
- **`runMutationAsync` was added to the IPC registry.** `branding:choose` is the
  first handler that awaits; the existing synchronous `runMutation` would have
  returned `{ ok: true, data: Promise }` and turned every refusal into an
  unhandled rejection. The catch half is shared so the two cannot diverge.
- **`BrandingSlotState` is `{ state: 'present' | 'absent' }`**, not the
  `{ kind: 'default' | 'custom' }` sketch in T-260829-05's and T-260829-07's
  scopes. The shipped schema won over the scopes written before it existed.

  prompt and still produces the wrong shape. Now scoped to the real residual
  risk: `applyRenames` substitutes over raw JSON text, so a future column
  renamed from `name` or `type` would rewrite more than intended.

## What went wrong

**One cross-branch failure, caught by the gate and nothing else.**
`App.test.tsx` asserted `getByText('Solo CRM')`. T-260829-06 deleted the
`.rail-app` name span the mockup carried, and T-260829-07 moved the accessible
name onto the brand container — so by the time both had merged the text node was
gone. Each branch was green alone. It lives in `runtime-boot-renderer`, a serial
pool neither builder ran despite both being told to run `--project=renderer` in
full, because that flag does not cover it. **The dispatch instruction was wrong,
not ignored** — "run its whole project" names the wrong project for anything the
`App` smoke test mounts. Fixed at merge by reading the name off the element that
now carries it, and the replacement assertion was mutation-checked.

**Two scopes were wrong about the repository, and both cost a builder time to
discover.** T-260829-04's Touches names the migrations `meta` journal, which
holds only `0001_init` — 0002 through 0005 were never added, because migrations
register in `index.ts`. And T-260829-10's plan for the drift test could not work
at all: drizzle-kit cannot express a rename without an interactive prompt that
aborts with no TTY. Both builders investigated and reported rather than forcing
the scope; the second found a genuinely better answer (move the diff's *base*
rather than relax the assertion). But scopes are written from the code and these
two were written from an assumption about it.

**The security-review skill reviewed the wrong thing.** Invoked directly, it
diffed against `origin/main` — 212 commits behind — and swept the entire project:
3.3MB of diff across every file in the repo. It had to be re-run as a scoped
subagent against `main..T-260829-05` (ten files, 61KB) to be useful. The skill
assumes a branch pushed against a current remote; this repo's `origin/main` is
far behind local `main`.


**A follow-up scope written during this run was wrong, and it was the
orchestrator's.** T-260829-12 asked for a post-rename snapshot from
`drizzle-kit generate`, run interactively, on the assumption that what it
writes could serve as the drift test’s base. It cannot: it describes the full
current schema, not the mid-history state, so following that scope would have
deleted the assertions tying `schema.ts` to the migrations' own SQL — a
weakening, dressed as bookkeeping. Caught only because the blocker was probed
before being handed to the user as a command to run. The same failure mode as
the two builder-facing scopes above: written from an assumption about the tool
rather than from the tool.

**T-260829-08 was worse than scoped.** Eleven dead call sites, not nine:
`CompaniesGrid` and `PeopleGrid` took `openSheet` through an `onCreate` prop
whose type *restated* the old signature, so the grid "Add company" cards were
broken the same way and the scope's own table missed them.

**Most of this run's acceptance is still outstanding**, and it is the half a
machine cannot do. T-260829-06 and -07 between them need a real 230px Electron
window: upload an icon and watch the rail change without a reload, upload a tall
near-square logo (the aspect-ratio case actually worth seeing), choose an `.svg`
and read the refusal, cancel a picker, restart and confirm both images survive.
T-260829-08 needs six create paths driven by hand on an empty database. All of it
belongs with [T-260828-15](../../tasks/202608/T-260828-15-real-window-qa-pass.md),
which was already open before this run and is the gate that would have caught the
dead create buttons in the first place.

**On review method:** every merge was mutation-tested rather than read — 19
mutants across the seven tasks, all of which turned a test red. That found no
defects this time, which is itself the result worth recording: the builders'
tests could fail. The two cheapest and most informative were crossing the two
branding slots in the rail, and relaxing the byte cap by one.
