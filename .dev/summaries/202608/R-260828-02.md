## Decisions

- **[ADR-006](../../decisions/ADR-006-data-root-pointer-file.md)** — the data
  root resolves through a pointer file, so its location can be a choice. Absence
  of the pointer *is* the default; nothing is written for "use the default".
- **[ADR-007](../../decisions/ADR-007-entity-schemas-in-shared.md)** — entity
  schemas live in `electron/shared/`, so one zod definition serves both sides of
  the IPC boundary.
- **[ADR-008](../../decisions/ADR-008-search-index-shape.md)** — the search index
  shape: a union view as FTS5's content relation, with `rowid * 8 + <kind code>`
  encoding. **The kind codes are append-only**, and renumbering one without a
  full rebuild silently repoints already-indexed rows at the wrong table.
  Superseded in part by ADR-009 in the next run, which kept the encoding and
  materialised the relation.
- **`vitest.config.ts` grew a serial pool** (T-260828-47) for the five files that
  boot a real Electron instance or a full render tree, and then a conditional
  worker cap (T-260828-54) for runs inside an agent worktree.

## What went wrong

**Three healthy branches were reported `verify-failed` for timeouts that did not
reproduce.** The cause was concurrency, not defects: the median suite run went
from ~20s at 2–5 concurrent agents to 44s at 6–7, because each agent's vitest
sized its worker pool from the whole machine — six agents meant 28 workers on 8
cores. T-260828-54 closed it by capping workers inside agent worktrees and moving
two more files to the serial pool; six concurrent runs then went green.

**T-260828-54 itself defeated two subagents before being done in-session.** The
first ran 43 minutes and committed nothing, stuck in an `until grep` loop polling
its own background measurement harness; the second ran 31 minutes and was writing
another. The task needed a *quiet machine* to measure, which is the one thing a
wave cannot provide, plus several multi-minute measurements whose results decide
the next step.

**A measurement reported to the user was itself wrong.** `App.test.tsx` was
described as failing 2 runs in 3 "on a quiet machine". The machine was not quiet
— the second T-54 subagent was running its load experiment at the time. Measured
properly it passed 5/5 at 1.3s. The lesson kept: *a measurement taken during a
wave is a measurement of the wave.*

**Isolation worktrees start at the session's opening commit, not `main`.** One
builder found no task file, searched `git log --all`, and reported *"blocked — the
scope does not exist anywhere in git history"*. It was tracked on main the whole
time. The subagent preamble now opens with an unconditional
`git checkout -B <task-id> main`, stated as a fact rather than as a check to
perform.

**And this summary was not written.** That is the failure this run's record most
needed to note, and the one it could not, because nobody wrote it. See the note
at the top.
