built it. Fanning out a worktree subagent for a single pure function would have
cost more in dispatch and merge than the change itself. That also removes the

## What changed

The drift test that stands between `schema.ts` and the checked-in migrations
derives its base by replaying 0006's renames over 0001's snapshot. It did that
by substituting over the snapshot's raw JSON text. It now walks the parsed
object instead, so a future column renamed from `name` or `type` moves one
field rather than every field that happens to be spelled that way.

## Decisions

- **The rename moved to `electron/main/db/test-support/`, not into
  `migrations/`.** It is test-support: nothing under `electron/main` imports it
  at runtime, because the runtime applies checked-in SQL and never reads a
  snapshot. Putting it beside the migrations would have implied otherwise. The
  move is also what makes the tests cheap — `schema.test.ts` spawns
  `drizzle-kit` and lives in the serial `runtime-boot-node` pool, and a pure
  function does not belong behind a 60-second child process.
- **Conventional foreign-key names are recomputed, not substituted.** Drizzle
  derives `engagements_service_version_id_service_versions_id_fk` from the
  parts it joins, so once the parts move the name follows. A key whose stored
  name is *not* the derived one was named by hand and keeps it — as does every
  index, unique and check constraint name, which are literals a developer wrote
  in `schema.ts` and which SQLite's `ALTER TABLE … RENAME` does not touch
  either.
- **`renamesInMigrations` now returns statement order and tags each rename with
  its kind.** Forced by the structure rather than chosen: 0006 renames
  `service_versions` and then renames a column of the **new** name, so grouping
  renames by kind looks up a table that does not exist yet.
- **The `EXPECTED_TABLES` guard stays**, though a structural rename should make
  it redundant. Its comment now says why: it costs a set comparison and fails in
  one readable place, where a base that has quietly gone wrong otherwise
  surfaces as an unreadable mismatch against 0004 and 0005 much further down.
- **The `data` category's default extra gate (`architecture-review`) was not
  run**, and that is a judgement, not an omission: no schema, migration,
  repository or ADR-bearing decision moved. What moved is the test that guards
  them, and the guard on *that* is the mutation pass below.

## What went wrong

**The drift test's most important failure message could not be printed, and had
not been printable since T-260829-10.** Renaming a table in `schema.ts` with no
matching migration does fail the test — but the failure never reached the
terminal. drizzle-kit's abort message carries a stack trace; the assertion
interpolated it verbatim; and vitest parses assertion *messages* for stack
frames exactly as it parses real ones. `at render10 (…\drizzle-kit\bin.cjs:
1450:31)` sent it to read a source map out of drizzle-kit's bundle, which threw
`SyntaxError: Unexpected end of JSON input` **inside the reporter**. The run
then reported `Tests 22 passed (27)`, one unhandled error, and *no failed test*
— a failing gate that reads as a passing one to anything scanning for a red
line.

It was found only because this task's acceptance criteria said the message had
to be *performed*, not reasoned about. Reasoning about it would have concluded
it worked: the assertion is right there in the file, well written, and unchanged
for a week. Confirmed pre-existing by reproducing it against `HEAD`'s copy of
the file before any of this task's changes, so it was not something the rename
introduced. Fixed by stripping `at …` frames from the interpolated output and
keeping the line that says why.

**Two mutants survived the first pass**, and both pointed at the same hole: the
whole-identifier property — the entire point of the task — was asserted for
snapshot *keys* and nowhere else. Substring matching in the column-list swap
passed all nineteen tests, and so did substring matching in `renamedTableName`,
because the real rename set does not distinguish the two (`service_versions`
does not contain `services`). Both now have a fixture built to distinguish them:
a column `service_id_note` beside `service_id`, and the table names
`service_versions_archive` and `legacy_services`.

**A new test failed at its own baseline for a missing import.** Three
`renamedTableName` tests were written and run before the symbol was imported;
the mutation pass surfaced it immediately, and `typecheck` would have caught it
at the gate regardless. Cheap, but worth recording as the reason the mutation
pass is run against a green baseline first rather than assumed green.

## On method

The structural rewrite was **proved equivalent to the implementation it
replaced before being trusted** — a throwaway test applied both to the real 0001
snapshot and compared results byte for byte, and was itself mutated to confirm
it could fail. Deleted afterwards, since keeping it would have meant keeping the
old implementation forever. For a change whose entire risk is "the new version
quietly covers less than the old one", that comparison was worth more than any
amount of reading the diff.
