## Decisions

**T-260829-14 declines P2-04's ADR-003 allowance for provisional revenue
figures.** §6.1 specifies a hero row of recurring monthly revenue, fixed
backlog, open todos and cadence health; the mockup computes the first two live
off engagement columns, which is exactly what AGENTS.md's revenue gotcha
forbids porting. P2-04's acceptance grants an allowance to do it anyway with
the figures marked provisional. This run does not take it: `revenue_lines` is
empty until Phase 3, so the allowance buys a number that is not provisional
but absent, in exchange for writing the per-model branching AGENTS.md names as
the project's highest-risk carry-over — and then deleting it at P3-05. Two
counts that are true today (active engagements, companies) stand in. The
deviation is written into the task file itself so a later reader does not
"fix" it back. Scoped and approved before the run, not decided mid-flight.

**`CADENCE_SETTING_KEY` moved to `electron/shared/settings.ts`** (T-260829-13).
It had lived in `WorkspaceSettings.tsx` as that view's private map. A second
reader now exists — `renderer/lib/decay.ts`, resolving a null `cadence_days`
against the kind default — and a pure computation cannot import from a view
without dragging a React tree into its test. ADR-002 rule 3 already names
`settings.ts` as the one module where keys are declared, so this is where it
belonged; no ADR needed, the rule was already written.
