## The real-window pass (T-260828-15)

jsdom certifies structure, not paint: it computes no layout, so every width
and overflow assertion in this repo measures nothing at all.
`scripts/window-pass.mjs` (new) boots the built app against a throwaway,
freshly seeded profile and drives it over the Chrome DevTools Protocol,
recording geometry and a screenshot per route per width. It is deliberately
not wired into `npm test` — that would be the automated visual-regression
tooling T-260828-15's scope rules out, and that decision is still the user's.

No horizontal scroll at 1440, 900 or 700, measured in a real window; rail
off-canvas and unfocusable below 900; one gold hero value; focus ring 2px
solid verdigris.

It found three defects, all fixed, none of them reachable from the suite:

1. **Every cadence decay bar rendered at 0px, across four views.**
   `.decay .fill` is a `<span>`, therefore `display: inline`, and `width`
   does not apply to a non-replaced inline box. It computed `width: 100%`,
   animated to completion with `forwards`, and painted nothing. `.track`
   escapes only by accident, because `.decay` is a flex container and
   blockifies its children. Transcribed faithfully from the mockup, which
   carries the same declaration and cannot reveal it — its own Going quiet
   list is empty at the fixture's date. Shipping since T-260828-28.
2. **Three stylesheets declared the same unscoped `.tli` selectors**, so
   whichever the bundler emitted last styled all three views. Activity's flex
   meta row lost to the detail views' `display: block`, running the timestamp
   into the company name on Activity and in Today's Recent card.
3. **`npm run seed` produced a database the app refuses.** `waiting_since`
   was written with the date-only shifter against a `timestampSchema` column,
   so `tasks:list` failed its response schema and Today and Todos rendered
   "the response was not in the expected shape" instead of any content.

The guard added for (3) is the general one rather than a patch: the seed test
now reads every seeded row back through the repository the app calls and
parses it with the wire schema the IPC layer validates against, for all five
entity kinds. A field added to any of those schemas is covered without that
list changing. A neighbouring test also named `companies.last_touch_at` in
its title while never querying that column — fixed, with
`people.last_contact_at` added.

**A correction this run owes its own record:** T-260829-13's "Why" states that
`DecayMeter` "shipped in T-260828-11 and no view renders either one". Four
views render it. The claim came from a `grep -l … | head` truncated before the
`views/` entries — which is also why the decay defect initially read as
affecting one new view rather than four shipped ones. The task's value stands
(the arithmetic was still duplicated per view); its premise did not.

## Decisions

**T-260829-14 declines P2-04's ADR-003 allowance for provisional revenue
figures.** §6.1 specifies a hero row of recurring monthly revenue, fixed
backlog, open todos and cadence health; the mockup computes the first two live
off engagement columns, which is what AGENTS.md's revenue gotcha forbids
porting. P2-04's acceptance grants an allowance to do it anyway with the
figures marked provisional. This run does not take it: `revenue_lines` is
empty until Phase 3, so the allowance buys a number that is not provisional
but absent, in exchange for writing the per-model branching AGENTS.md names as
the project's highest-risk carry-over — and then deleting it at P3-05. Two
counts that are true today (active engagements, companies) stand in. A test
asserts the page renders no "recurring"/"backlog" text and no dollar sign, so
the omission cannot quietly regrow, and the reasoning is in `Today.tsx`'s
header so the next reader does not "fix" it back.

**The tour joins the layer stack as a sixth `'tour'` `LayerKind`** rather than
owning a `keydown` listener of its own. `LayerManager` holds the one
document-level Escape handler precisely so one keypress cannot close two
layers — `Sheet` passes `closeOnEscape={false}` for the same reason — and a
second listener would have reintroduced that bug. Pinned by a test: the
palette opened over the tour takes the Escape and the tour stays.

**`CADENCE_SETTING_KEY` moved to `electron/shared/settings.ts`.** It had lived
in `WorkspaceSettings.tsx` as that view's private map. A second reader now
exists — `renderer/lib/decay.ts` — and a pure computation cannot import from a
view without dragging a React tree into its test. ADR-002 rule 3 already names
`settings.ts` as the one module where keys are declared, so no ADR was needed;
the rule was already written.

**`onboarding.tourSeen` is a boolean, not a version number.** A boolean cannot
answer "seen which version of the tour", so adding a sixth step marks everyone
who saw the five-step tour as done. That is the right way round: the
alternative re-nags every operator on every edit to the copy, which is the one
failure mode that would make the feature worse than not having it. Written
into the key's own comment rather than left to be rediscovered.

## What went wrong

**Four mutants survived the builders' own checks, and every one of them was
the orchestrator's scope being too weak rather than a builder cutting a
corner.** All four were fixed at merge, each verified red-under-mutant and
green-restored:

- *The tour could come back after being skipped.* Removing the `autoOpenedRef`
  guard left all fourteen tests green. The close path writes `true` into the
  cache immediately, so only a refetch can put `false` back — and
  `settings:set`'s own success is what invalidates the snapshot, so a write
  that reports success without persisting refetches `false` within the same
  session and re-satisfies the auto-open condition. The overlay lands back on
  top of the person who just dismissed it: the exact failure the feature
  exists to prevent, with one unpinned line standing in its way.
- *Two of Today's four stat values were unasserted.* The acceptance asked that
  four stats **render**, and they did — so mutants making Cadence health read
  the total company count, and Active engagements count everything but `lost`,
  both passed. Visibly wrong numbers on the first screen of the app with a
  green suite.
- *The Going quiet sort's tiebreak was unpinned.* Dropping it passed. "Ordering
  on a non-unique column with no tiebreaker" is on `.dev/README.md`'s own list
  of defects this project has shipped before.

**The scope for T-260829-14 contained an arithmetic error, and the builder
caught it.** Its Going-quiet acceptance asked for a `channel` (cadence 30) 20
days quiet against a `client` (cadence 7) 9 days quiet. 20/30 is 0.67 — band
`warn` — so the channel never enters the list, and the pair would have
exercised the filter while appearing to test the sort. The builder used 35d/30
against 9d/7 and kept a 20d channel asserted *absent*. A scope's worked
example is as worth checking as its prose.

**The latency test failed the gate having passed everywhere else.** 58ms on
its branch and in isolation, 198ms against a 100ms budget in the full suite —
a wall-clock budget asserted while eight workers compete for CPU measures the
machine's load, not the view. `Today.test.tsx` moved into
`RUNTIME_BOOT_RENDERER_FILES`, whose header already states the rule ("a file
whose pass/fail depends on what else is running does not belong in a parallel
pool"). Nothing was weakened: the budget is still 100ms, the fixture still
asserts its own shape, and the serial-pool median is 57.58ms. This is the
third time a heavy jsdom file has been found this way, after T-260828-47 and
T-260828-54 — the pattern is now well enough established that a *new* file
which renders at volume should be added to that pool when it is written, not
after it fails a gate.

**The task template's `## Outcome` heading was missing from all three scope
files.** They were written by hand instead of copied from
`.dev/templates/task.md`, so each stopped at `## Risks`. `check:index` caught
it at the first close — the gate working — but it cost two round trips to
repair mid-merge rather than zero at scope time. `scope-task` should copy the
template, not reproduce it from memory.

**The two-dot diff nearly misled the review.** `git diff main..T-260829-15`
showed T-260829-13's merged work as deletions, because that branch was based
on a `main` from before it landed. The three-dot form is the one that answers
"what did this builder change". Worth stating because the misreading would
have been a blocking finding against work that was never touched.
